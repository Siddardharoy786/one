AWS Lambda

Type: Serverless compute service (Function as a service)
* For the instance we provide lambda to do the tasks automatically
* Purpose: Run individual functions in response to events (event-driven).(why it is not comes into PaaS means it is for individual not for the whole web.)
- With Lambda, you don’t run a continuous process.
- Instead, you upload a function (a small piece of code).
- That function is triggered by an event (like an API call, file upload, or database change).
- AWS automatically starts a container, runs your function, and then shuts it down.
- You don’t manage servers or processes — AWS handles all the infrastructure.

AWS Elastic Beanstalk

Type: Platform-as-a-Service (PaaS)
Purpose: Deploy and manage full applications (web apps, APIS).
- You upload your code to Elastic Beanstalk.
- Elastic Beanstalk automatically:
- Launches EC2 servers.
- Installs Python runtime.
- Configures load balancer.
- Sets up monitoring.
- Scales up if many users visit, scales down when traffic is low.
- Your app is live without you manually setting up servers.

Automatic Process (Lifecycle Rules)

Create a Lifecycle Policy for the bucket:
Day 0: Object in Standard.
After 30 days: Transition to Standard-IA.
After 60 days: Transition to One Zone-IA (optional).
After 90 days: Transition to Glacier.
After 365 days: Transition to Glacier Deep Archive.

AWS will automatically move objects based on these rules.

VPC (Virtual Private Cloud)

- This network helps them to set up firewall rules which help to protect the resources from network attacks.
- AWS resources in a virtual network defined by you. You choose the range of IP addresses for your VPC by using CDR notations.

COMPONENTS OF VPC:

Subnet:

- A range of IP addresses is called subnet.
- Public Subnet Bastion Host (accessible from the internet) (Internet Gateway + Security Group)
- Private Subnet Database EC2 instance (no direct internet access) (NAT Gateway Security Group)

Routing table:

- A set of rules that guides network traffic in your Amazon VPC is called a route table.
Internet Gateway (free of cost):
- It's a virtual device that enabled the communication between your VPC and the internet.
NAT Gateway (chargeable):
- It is an AWS-managed service that allows instances in a private subnet to access the internet or other AWS services, without exposing those instances to, inbound
internet traffic.
Security group:
- You can use multiple layers of security in the form of security groups and network access control lists
VPC endpoints:
- You can create private connection between your VPC and supported AWS services such as 53
VPC peering:
- This feature is for enabling communication between two vpc's over the private IP addresses VPC, peering is possible between the vpc's in different Aws regions

Amazon Relational Database Service (RDS) (three architecture):
- It is a managed service by AWS that makes it easy to set up, operate, and scale relational databases in the cloud.
- It removes the burden of tasks like hardware provisioning, database installation, backups, patching, and monitoring.

- RDS = For transactional workloads (day-to-day operations).

AWS monitoring and auditing services:

AWS Config
- Purpose: Tracks and records the configuration of AWS resources and evaluates compliance.
- ex: If an EC2 instance is launched with an unencrypted EBS volume, AWS Config marks it as NON-COMPLIANT.

AWS Trusted Advisor
- Purpose: Provides best practice recommendations for your AWS environment.
- ex:Trusted Advisor might recommend enabling MFA on IAM users or restricting public access to $3 buckets..

Amazon Inspector
- Purpose: Automated security assessment for EC2 and applications.
- ex: Inspector can detect unintended network access to an EC2 instance and suggest security group changes.

VPC Flow Logs
- Purpose: Captures IP traffic going in and out of network interfaces.

AWS CloudTrail
- Purpose: Logs all API calls and actions in your AWS account (records all API activity for auditing). 
- ex: If an IAM user deletes an EC2 instance, CloudTrail records the event with timestamp and user details.

Amazon CloudWatch
- Purpose: Monitoring and alerting for AWS resources and applications (triggers alarms.).

LEX Architecture Works (Step-by-Step)
Step 1: User Access
A user opens LEX want to view learning content

Step 2: CDN (CloudFront)
The request first hits CloudFront, AWS's Content Delivery Network.

Step 3: Load Balancer (ALB)
If the requested resource isn't cached, the request goes to Application Load Balancer (ALB). ALB distributes traffic across multiple servers (EC2 instances) to prevent overload and ensure high availability.

Step 4: Nginx Reverse Proxy
ALB forwards the request to Nginx, which acts as a reverse proxy.

Nginx decides where to send the request:

UI Static (Angular front-end) to make the interface visualize.
UI Proxy (Node.js API gateway)
Client Assets (Tenant-specific configs)

Step 5: Authentication
UI Proxy checks the user's token with Keycloak before accessing data.

Step 6: Application Tier (Microservices)
UI Proxy routes API calls to microservices:

Playlist Service Fetch playlists
Content Service - Get content from 53
Progress Service - Update learning progress

Step 7: Storage Tier
Content (videos, PDFs) is fetched from Amazon 53. Metadata comes from Neo4j, ElasticSearch, or PostgreSQL.

Step 8: Messaging
Events like "quiz completed" are sent to Kafka. 
e.g., updating progress, sending notifications.

Step 9: Deployment
All services run in Docker containers, managed by Kubernetes (EKS).

Example: User Watches a Video

User clicks Play Request goes to CloudFront.
CloudFront serves cached UI ALB routes to Nginx.
Nginx sends API call to UI Proxy Authenticated via Keycloak.
UI Proxy calls Content Service Fetch video from $3.
Video streams via CloudFront User watches.
Continue Learning Service stores resume point.

AWS Notes completed
Kafka sends event Progress Service updates user progress.
